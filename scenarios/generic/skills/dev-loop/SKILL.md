# 开发工作循环

1. 先读相关文件再改；一次只改一个任务范围内的文件。
2. 每完成一个逻辑单元就跑一次构建/测试，不要攒到最后。
3. 验证失败时按失败配方处理：
   - 依赖缺失 → 补 package/requirements，不要手写 vendor。
   - 类型错误 → 顺着调用链改，不要用 any 糊弄。
   - 测试失败 → 先看断言差异，再定位实现，不轻易改测试。
4. 新文件遵循项目现有目录结构；没有结构就建最小结构。
5. 不碰密钥文件；不执行下载二进制的命令；网络受限时用语言内置库解决。
